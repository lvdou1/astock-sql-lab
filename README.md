# A 股财务异常识别 · SQL 分析库

用 SQL 回答三个真实的投研问题：**谁在赚钱、谁在裸泳、数据本身可不可信。**

一个 `python run.py` 就能跑起来，不需要装数据库、不需要联网、不需要任何账号。

```bash
pip install -r requirements.txt
python run.py
```

<p align="center"><i>22 只 A 股 · 25,914 条日线 · 418 期财报 · 建库到出结果不到 1 秒</i></p>

---

## 这个项目解决什么问题

大多数人写 SQL 项目是"50 道练习题"，面试官看不出你会不会做业务。这个项目反过来：**每个查询都对应一个投研或风控的实际决策**。

| # | 业务问题 | 换成业务语言 |
|---|---|---|
| 1 | 2022 年至今谁赚得最多？ | 选股业绩归因的起点 |
| 2 | 每只股票在行业内排第几？跑赢基准多少？ | 相对收益考核，绝对收益不算数 |
| 3 | 历史上最惨的一笔回撤有多深、从哪天开始？ | 持仓体验与风险预算 |
| 4 | 最新报告期谁的应收、存货在恶化？ | 财报排雷的前置筛选 |
| 5 | 哪些公司同时踩中多条财务异常规则？ | **本项目的核心：规则引擎** |
| 6 | 这份数据本身干不干净？ | 数据岗面试必问的那道题 |

## 三个结论

**一、回撤比收益诚实得多。** 22 只股票里只有 6 只正收益，收益中位数 -9.46%；但最大回撤中位数是 **-42.47%**。收益只看首尾两天，回撤要你扛住中间每一天。

**二、银行股抗跌是刻板印象。** 工商银行最大回撤仅 -10.04%，但兴业 -24.7%、招商 -41.12%、平安 -42.57%——同一行业内部差 4 倍，得看具体标的，不能按板块贴标签。

**三、SQL 只能发现异常，不能判定异常。** 评分最高的五粮液，命中的两条规则集中在 2025 年报单期：毛利率从 60% 跌到 50.3%，次年一季度又回到 65.1%。这种"单期突变后立刻回归"的形态，**更可能是数据口径差异而不是经营恶化**，实操中必须回原始年报核对。这句话比任何一条 SQL 都重要。

## 数据模型

标准星型结构，2 张维度表 + 2 张事实表：

```
dim_industry ──1:N──> dim_stock ──1:N──> fact_daily_quote
                          └──────1:N──> fact_financial
```

| 表 | 粒度 | 行数 | 说明 |
|---|---|---|---|
| `dim_industry` | 行业 | 10 | 申万一级 + 自定义一级归类 |
| `dim_stock` | 股票 | 22 | 含 `board`（板块）与 `is_st` |
| `fact_daily_quote` | 股票 × 交易日 | 25,914 | 价格**已后复权** |
| `fact_financial` | 股票 × 报告期 | 418 | 比率口径，19 期 |

设计细节见 [`docs/DATA_DICT.md`](docs/DATA_DICT.md)，包括为什么复合主键、为什么保留银行股、为什么用后复权。

## 用了哪些 SQL 技巧

| 文件 | 核心技巧 | 对应面试高频考点 |
|---|---|---|
| `01_区间收益.sql` | 条件聚合首尾取价 `MAX(CASE WHEN ...)` | 避免多次子查询 |
| `02_行业排名.sql` | `ROW_NUMBER` + `MEDIAN() OVER` | 窗口函数做分组排名与基准 |
| `03_最大回撤.sql` | 累计最大值 `ROWS UNBOUNDED PRECEDING` + `arg_min` | 时间序列上的运行态指标 |
| `04_同比口径对齐.sql` | 自关联按 `MONTH`/`DAY` 对齐、`YEAR` 差 1 | **累计口径不能直接比，必考** |
| `05_财务异常评分.sql` | 条件聚合打分 + `FILTER` 子句分近期/历史 | 规则引擎、单查询多统计 |
| `06_数据质量.sql` | `UNION ALL` 体检表 | 数据质量保障 |

`05` 里有个细节值得单独看：**为什么经营现金流那条规则只判「由正转负」**。因为 A 股财报是累计口径，一季度经营现金流天然常为负（本项目数据里 110 条一季报有 31 条为负，占 28%），直接判 `ocf < 0` 会误伤近三分之一样本。

## 关于数据

| 项目 | 说明 |
|---|---|
| 行情 | 腾讯财经，**后复权**日线，2022-01-04 ~ 2026-11-16 |
| 财务 | 新浪财经，比率口径（同比增速、周转天数、利润率等） |
| 获取 | `python scripts/fetch_data.py`（已附带数据，无需重跑） |
| 行业 | 申万一级手工归类，权威分类请以中证/申万官方文件为准 |

**已知限制**（写在明面上，因为它们也是分析的一部分）：

1. **样本只有 22 只大市值股票**，不是全市场。所有统计结论只在这个池子里成立，不能外推。
2. **财务数据是比率不是绝对额**，因此做不了"应收账款增速 vs 营收增速"这类绝对额对比，只能做周转天数同比。
3. **银行 4 家没有应收/存货科目**，涉及这两项的统计已显式排除金融行业。
4. **ST康美的造假期（2018-2020）在数据窗口之外**，所以它拿不到高分——这是窗口限制，不是规则失效。
5. 本项目用于学习与展示，**不构成任何投资建议**。

## 为什么用 DuckDB

单文件、零配置、`pip install` 即可，而且窗口函数与 Postgres 完全兼容。面试官 clone 下来 10 秒能跑出结果——**能跑起来的项目才有价值，跑不起来的等于没有**。

换成 MySQL/Postgres 需要装服务、建用户、配连接串，多数人走到第二步就放弃了。
