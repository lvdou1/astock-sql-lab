# 中证800 财务异常识别 · SQL 分析库

用 SQL 回答三个真实的投研问题：**谁在赚钱、谁在裸泳、数据本身可不可信。**

一个 `python run.py` 就能跑起来，不需要装数据库、不需要联网、不需要任何账号。

```bash
pip install -r requirements.txt
python run.py
```

<p align="center"><i>799 只 A 股（中证800 成分）· 916,544 条日线 · 15,113 期财报 · 30 个行业 · 建库到出结果不到 7 秒</i></p>

---

## 这个项目解决什么问题

大多数人写 SQL 项目是"50 道练习题"，面试官看不出你会不会做业务。这个项目反过来：**每个查询都对应一个投研或风控的实际决策**。

| # | 业务问题 | 换成业务语言 |
|---|---|---|
| 1 | 2022 年至今谁赚得最多？ | 选股业绩归因的起点（统一评估窗口） |
| 2 | 每只股票在行业内排第几？跑赢基准多少？ | 相对收益考核，绝对收益不算数 |
| 3 | 历史上最惨的一笔回撤有多深、从哪天开始？ | 持仓体验与风险预算 |
| 4 | 最新报告期谁的应收、存货在恶化？ | 财报排雷的前置筛选 |
| 5 | 哪些公司同时踩中多条财务异常规则？ | **本项目的核心：规则引擎** |
| 6 | 这份数据本身干不干净？ | 数据岗面试必问的那道题 |

## 四个结论

**一、平均收益在金融数据里是骗人的。** 730 只（区间内全程有数据）收益中位数 **-0.78%**，均值却是 **+26.66%**——差了 34 倍。因为长尾被极端值撑起来了：寒武纪 +1259%、中际旭创 +1257%，而中位数告诉你"一半以上的股票五年没赚钱"。分指数看更清楚：沪深300 中位 +8.44%（153/282 正收益），中证500 中位 -2.73%（206/448），这五年大盘跑赢中盘。

> 为什么是 730 而不是 799：2022 年后上市的新股窗口比别人短，累计收益不可直接排名（德明利 2022-07 上市，按累计涨幅会排第一，但它少了 6 个月）。Q1/Q2 统一了评估窗口，Q6 里能看到 175 只交易日不足的明细。

**二、-90% 和 -10% 是两种产品。** 全池最大回撤中位数 -53.46%。恩捷股份从高点跌掉 **90.00%**，天合光能 -86.87%，基本等于跌到脚踝；而建设银行 -9.88%、工商银行 -10.04%，几乎没怎么跌。只看收益排名会把这两类东西放进同一个榜单，按波动率分层才是配置盘的做法。

**三、金融业必须整类剔除，不能只剔除空值。** 银行没有应收/存货科目（全 NULL），这个好识别。但非银金融**有**应收科目，口径却完全不同——券商的应收主要是客户保证金和清算款，湘财股份的应收周转天数算出来是 **8,910 天（24 年）**，不是造假，是分母口径错了。如果只按 `IS NOT NULL` 过滤，湘财会被评成高风险。这是本项目最典型的一次误报。

**四、数据质量要分"规则内"和"真异常"。** 全池有 5 条单日涨跌幅超过 ±21% 的记录，看着像脏数据。查下去：4 条来自合合信息（688615）上市前 5 个交易日——注册制新股这 5 天不设涨跌幅限制，是规则不是错误；剩下 1 条是中孚实业重组复牌当日。**如果不区分，要么误报一堆，要么把阈值放宽到 ±100% 而漏掉真问题。**

## 数据模型

标准星型结构，2 张维度表 + 2 张事实表：

```
dim_industry ──1:N──> dim_stock ──1:N──> fact_daily_quote
                          └──────1:N──> fact_financial
```

| 表 | 粒度 | 行数 | 说明 |
|---|---|---|---|
| `dim_industry` | 申万一级行业 | 30 | 含自定义大类 `industry_level` |
| `dim_stock` | 股票 | 799 | 含 `board`、`index_membership`、`is_st` |
| `fact_daily_quote` | 股票 × 交易日 | 916,544 | 价格**已后复权** |
| `fact_financial` | 股票 × 报告期 | 15,113 | 比率口径，19 期 |

设计细节见 [`docs/DATA_DICT.md`](docs/DATA_DICT.md)，包括为什么复合主键、为什么用 Parquet、为什么保留金融股。

## 用了哪些 SQL 技巧

| 文件 | 核心技巧 | 对应面试高频考点 |
|---|---|---|
| `01_区间收益.sql` | 条件聚合首尾取价 `MAX(CASE WHEN ...)` | 避免多次子查询 |
| `02_行业排名.sql` | `ROW_NUMBER` + `MEDIAN() OVER` | 窗口函数做分组排名与基准 |
| `03_最大回撤.sql` | 累计最大值 `ROWS UNBOUNDED PRECEDING` + `arg_min` | 时间序列上的运行态指标 |
| `04_同比口径对齐.sql` | 自关联按 `MONTH`/`DAY` 对齐、`YEAR` 差 1 | **累计口径不能直接比，必考** |
| `05_财务异常评分.sql` | 条件聚合打分 + `FILTER` 子句分近期/历史 | 规则引擎、单查询多统计 |
| `06_数据质量.sql` | `UNION ALL` 体检表 + 规则内外分层 | 数据质量保障 |

两个值得单独看的细节：

- **`05` 里为什么经营现金流只判「由正转负」**：A 股财报是累计口径，一季度经营现金流天然常为负（本数据 15,113 条财务记录里，一季报约三成 `ocf_ps < 0`），直接判 `ocf < 0` 会误伤大量正常公司。
- **`06` 为什么把极端涨跌幅拆成两行**：一行是"新股前 5 日，规则内"，一行是"非新股，需核查"。这个拆法是数据质量报告和"跑个脚本看看有没有空值"的分界线。

## 关于数据

| 项目 | 说明 |
|---|---|
| 股票池 | 中证800（沪深300 + 中证500），实际 799 只 |
| 行情 | 腾讯财经，**后复权**日线，2022-01-04 ~ 2026-11-16 |
| 财务 | 新浪财经，比率口径（同比增速、周转天数、利润率等） |
| 行业 | 申万一级（31 个），本项目覆盖 30 个 |
| 获取 | `python scripts/fetch_data.py`（约 9 分钟，已附带数据，无需重跑） |

**已知限制**（写在明面上，因为它们也是分析的一部分）：

1. **样本是中证800 成分股**，即大中盘蓝筹，不含微盘股与 ST 股。所以没有 ST 标的、财报质量整体偏好，异常评分天然偏保守。
2. **财务数据是比率不是绝对额**，因此做不了"应收账款增速 vs 营收增速"这类绝对额对比，只能做周转天数同比。
3. **金融业 85 只被排除在异常评分之外**（银行 24 + 非银 61），原因见结论三。
4. **行业分类为申万一级**，个别公司的主营业务可能与分类不完全一致。
5. 本项目用于学习与展示，**不构成任何投资建议**。

## 为什么用 DuckDB + Parquet

单文件、零配置、`pip install` 即可，窗口函数与 Postgres 完全兼容。**面试官 clone 下来几秒能跑出结果——能跑起来的项目才有价值。**

数据侧用 Parquet 而不是 CSV：91 万行日线存 CSV 要 25 MB 且没有类型，Parquet + ZSTD 压到 18.4 MB，`read_parquet()` 一行就带 schema 入库，不需要手写字段类型。维度表反过来用 CSV——行数少、人要能直接打开看。

如果换成 MySQL/Postgres，得装服务、建用户、配连接串，多数人走到第二步就放弃了。
